# 디자이너용 변경 설명서

최종: 생성 (시도 2)

실행 `20261008-131136` · 시도 2 에서 검사를 통과한 빌드 · 커밋 `3468b75658b7`.

이 파일은 구조 시안의 설명이다. 색·글꼴·간격 같은 시각 디테일은 평가하지 않았다. 화면 구성과 흐름, 그리고 바꾼 이유를 옮겨 적는다.

## 화면 대응

| 원본 | 재설계 |
|---|---|
| home | home |
| recipient | recipient |
| bank | bank |
| account | account |
| amount | amount |
| confirm | confirm |
| password | password |
| done | done |
| err-account | account |
| err-bank | bank |

재설계 화면의 순서와 하는 일:

1. `home` — 출금할 계좌를 알아보고 이체를 시작한다. 기존 다른 서비스도 이용한다.
2. `recipient` — 새 계좌 직접 입력 또는 기존 계좌 목록에서 받는 대상을 정한다.
3. `account` — 받는 계좌번호를 입력하고 선택한 은행을 확인한다. 계좌번호 오류도 이곳에서 고친다.
4. `bank` — 은행 또는 증권사를 찾아 선택한다. 은행 오류가 있으면 안내를 읽고 다시 선택한다.
5. `amount` — 출금계좌와 받는 계좌를 보며 보낼 금액을 입력한다.
6. `confirm` — 받는 계좌, 금액, 출금계좌, 수수료와 메모를 확인하고 필요한 항목을 수정한다.
7. `password` — 출금계좌 비밀번호 네 자리를 입력하고 최종 이체를 승인한다.
8. `done` — 이체 완료와 송금 내역을 확인하고 홈, 추가이체, 상세보기 또는 공유로 이동한다.

- **D14** `password` 재배열 키패드, 삭제, 닫기 — 앞선 숫자판과 다른 숫자 위치 때문에 이전 위치를 기억해 잘못 누를 수 있다. 실수를 고치려다 재배열을 누르면 위치가 다시 바뀌며, 닫기를 누르면 확인 화면 대신 홈으로 나간다. (근거[화면+코드]: 그림 12 숫자는 앞선 그림 6과 다른 순서이고, 아래쪽에 재배열과 삭제 기호가 있다. 코드의 buildPwPad는 숫자를 섞고 pw-shuffle도 다시 섞는다. 상단 닫기는 back-home으로 연결된다.)
- **D15** `done` 완료 요약과 확인 버튼 — 금액은 보이지만 누구의 어느 계좌에 보냈는지 완료 화면에서 다시 확인할 수 없다. 확인이 홈으로 돌아가는 버튼인지도 문구만으로는 알기 어렵다. (근거[화면+코드]: 그림 13 큰 완료 문장에는 '아래 계좌로'와 금액만 있고 은행 및 계좌번호가 없다. 아래에는 공유와 확인이 있으며, 코드의 finish는 홈 화면으로 이동한다.)
- **D16** `err-account` 계좌 오류 팝업 — 오류 코드가 먼저 눈에 들어오고, 확인을 누르면 무엇을 할 수 있는지 알기 어렵다. 오류를 닫은 뒤 다시 틀린 계좌번호의 수정 위치를 찾아야 한다. (근거[화면+코드]: 그림 14 팝업 첫 줄에는 붉은 ELB00016이 크게 표시되고, 계좌번호와 긴 오류 문장 아래에는 확인 버튼 하나만 있다. 코드의 close-error는 오류 발생 전 화면으로 돌아가며 입력란을 여는 동작은 없다.)
- **D17** `err-bank` 은행 오류 설명과 복귀 경로 — 은행 선택이 틀렸는데 계좌번호를 고치라는 안내를 따라 올바른 계좌번호를 지울 수 있다. 확인을 눌러도 은행을 고르는 곳으로 가지 않아 같은 오류를 반복할 수 있다. (근거[화면+코드]: 그림 15에는 붉은 ETA00325 아래 '과목코드 오류'와 '입력하신 계좌번호를 확인해주세요'가 보인다. 코드의 send에서 은행 불일치로 이 오류를 띄우며, close-error는 은행 선택이 아니라 confirm으로 돌아간다.)
- **D18** `account` 뒤로 이동한 뒤 재진입하는 동작 — 입력 방법을 다시 확인하려고 이전 화면에 갔다가 돌아오면 입력한 은행과 계좌번호가 사라져 처음부터 다시 해야 한다. 은행만 고친 뒤 금액도 다시 입력해야 할 수 있다. (근거[코드]: 코드의 go-account는 S.account를 빈 문자열, S.bank를 null로 초기화한다. account-next는 계좌번호 검사를 통과할 때마다 S.amount를 0으로 초기화한다.)
- **D19** `home` 다른 메뉴 및 부가 기능의 클릭 반응 — 이체 대신 다른 메뉴를 잘못 누르거나 실제로 사용하려고 누르면 아무 변화가 없어, 눌렀는지 모르고 반복 조작할 수 있다. (근거[코드]: 코드에서 메시지, 지갑, 알림, 전체메뉴, 홈의 여러 서비스와 하단 메뉴뿐 아니라 수취인 목록, 출금계좌 변경, 완료의 상세보기·공유 등에 해당하는 oos 동작이 모두 빈 분기로 끝난다.)
