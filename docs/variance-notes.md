## 데이터를 도구가 지키게 한 변경 (2026-10-05, `feat/data-preservation`)

Run 5 의 결론 — 말로 지시하는 방법은 효과가 없었다 — 뒤에 한 일이다. 프롬프트를
고치는 대신, 선택지 데이터를 **도구가 들고 있다가 모델의 답에 넣는다**.

    뽑기  입력 HTML 의 스크립트 배열로 그려지는 선택지를 이름과 원소로 꺼낸다
          (`senior_ui/restructure/preserve.py`). 선택지 집합을 모으는 방식은
          검사 I 와 같고, 마크업에 직접 쓰인 선택지(숫자판 등)는 대상이 아니다.
          원본에서 나오는 것은 `{BANKS: 38, SECS: 29, nums: 10}` 이다.
    넣기  재설계 HTML 의 첫 스크립트 앞에 `<script id="preserved-data">
          window.PRESERVED = {…}</script>` 를 넣는다. 모델이 같은 이름을 배열
          리터럴로 다시 선언하면 그 **초기화 식만** 참조로 바꾼다.
    검사  스크립트가 그 이름을 읽는지 형식 검사 단계에서 본다 (브라우저 없음).
          읽지 않으면 검사기까지 가지 않는다.

검사 I 도 함께 바꿨다. 그러지 않으면 데이터 블록이 모든 값을 원문에 넣어 주므로,
모델이 하나도 그리지 않아도 통과한다 — 데이터를 지키려고 만든 장치가 그 데이터를
지켰는지 보는 검사를 꺼 버린다. 이제 검사 I 는 블록을 뺀 원문과, 걷는 동안
렌더링된 DOM 에서 모은 선택지 값을 함께 본다.

지표가 둘로 나뉘었다. `choice_values_kept` 는 두 곳 어디에든 있는 값의 수이고
판정 기준이다. `choice_values_selectable` 는 그중 DOM 에서 실제로 고를 수 있던
값의 수다. 둘이 다르면 **경고** 하나가 난다 — fatal 이 아니다. "전체 보기" 뒤나
검색 결과로만 목록을 내놓는 설계는 검사기가 그 버튼을 누르지 않으면 DOM 에
나타나지 않으므로, fatal 로 하면 정상 설계가 떨어진다.

**Run 1·2·3 의 수치 변화.** fatal 은 바이트까지 같다 (셋 다 fatal 3, `pick-bank`
67개 중 58개 누락). warning 은 3 → 4 로 하나 늘었고, 늘어난 1건은 전부 `케이뱅크`
하나다. 그 값은 세 빌드의 은행 추정표(`const PREFIX = {'1111':'케이뱅크'…}`)에만
있어 문서에는 남아 있지만 고를 수 있었던 적이 없다. 즉 새 경고가 처음부터 겨냥한
바로 그 상태다. 원본 대 원본은 fatal 0 / warning 2 로 그대로다.

**API 없이 세 경우를 확인한다** (`--mock`). 다섯 모드가 Run 1 빌드의 은행 목록
한 줄에서만 다르다 (`senior_ui/restructure/model.py` 의 `MOCKS`).

| 모드 | 그 한 줄 | 결과 |
|---|---|---|
| `preserved-all` | `PRESERVED.BANKS.concat(PRESERVED.SECS)` | **통과** (fatal 0 · warning 3) |
| `preserved-some` | 같은 것 + `.slice(0, 4)` | **검사 I** fatal 1 (67개 중 57개 누락) |
| `preserved-none` | 네 개를 직접 쓴다 | **형식 검사** 실패, 검사기까지 가지 않음 |

`preserved-all` 은 원본 숫자판의 `00` 과 금액 버튼의 `전액` 도 채운다. 채우지
않으면 그 두 누락 때문에 "전부 그린 답" 도 떨어져서, 통과하는 모습을 볼 수 없다.

## 표 2. 방식 간 차이 — 손수 제작 vs 자동 파이프라인

**이 표는 편차의 근거가 아니다.** 각 방식의 표본이 부족해(손수 제작 3회, 자동 4회)
차이가 방식 때문인지 실행 간 흔들림인지 가릴 수 없다. 관측 기록일 뿐이다.

| 유형 | 손수 제작 (Run 1·2·3) | 자동 파이프라인 (Run 2·3·4) |
|---|---|---|
| 입력 방식 | 전부 숫자판 | Run 2 는 `<input>`, Run 3 은 숫자판, Run 4 는 혼용 |
| 화면 수 | 9 · 7 · 8 | 6 · 8 · 7 |

입력 방식은 자동 쪽 안에서도 갈린다. 자동 Run 2 만 `<input>` 을 썼고 Run 3 은
손수 제작과 마찬가지로 숫자판이다. 방식의 차이라고 부를 근거가 더 약해진다.

숫자판과 입력창은 고령자에게 과제 완수율이 갈릴 수 있는 차이다. 실험 자극물을
고를 때 이 항목이 고정되지 않으면, 결과를 도구의 효과로 귀속시킬 수 없다.

  자동은 아직 4회뿐이라 표로 만들지 않는다.
