# 편차 기록

같은 프롬프트로 재구성을 돌릴 때마다 무엇이 달라지는지 모아 둔다. 편차의 종류를
쌓는 것이 목적이고, 어느 설계가 낫다는 판단은 여기서 하지 않는다.

손으로 만든 Run 1·2·3 의 비교는 `restructure-runs.md` 에 있다. 이 문서는 그 뒤에
`tools/run_restructure.py` 로 자동 생성한 것들을 기록한다.

## Run 2 (2026-09-30)

- 화면 6개: `start` · `who` · `amount` · `confirm` · `password` · `done`
- `who` 화면에 은행 선택 + 계좌번호 입력 동시 배치
- Run 1 은 같은 지점을 두 화면으로 분할했음
- 편차 유형: 화면 수(9·7·8)에 이어 **"분할 경계"** 에서도 불일치 확인

실행: `outputs/restructure_auto/20260930-145811/` (gpt-4o, `--stage wireframe`,
3회 시도 중 3회차가 흐름 검증 통과 후 audit 도달)

## 지금까지 확인된 편차의 종류

| 유형 | 관측 |
|---|---|
| 화면 수 | 9 · 7 · 8 (손수 제작 Run 1·2·3), 6 (자동 Run 2) |
| 분할 경계 | 계좌번호와 은행을 한 화면에 둘 것인가 나눌 것인가 — Run 1 은 분할, 자동 Run 2 는 합침 |
| 확인 지점 | 돈이 나가기 전 명시적 예/아니오 3 · 1 · 3 회 |
| 입력 방식 | 숫자판(손수 제작 전부) vs `<input>` 필드(자동 Run 2) |

앞의 둘은 `restructure-runs.md` 에서, 뒤의 둘은 자동 실행에서 나왔다.
