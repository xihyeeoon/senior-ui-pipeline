# 원본 HTML 대 Flutter A1 이체

본실험은 Flutter 더미앱(`senior-ui-dummy-app`)으로 하고, 재설계 결과는 그 앱의 C
조건이 된다. 재설계의 입력인 `inputs/original_transfer.html` 은 참가자가 보는 A1
이체 화면과 같아야 한다. 이 문서는 둘을 화면마다 비교한 것이다 (2026-10-05, 코드
수정 전).

비교 대상은 화면 흐름 · 문구 · 누를 수 있는 요소 · 입력 방식 · 데이터 · 오류
동작이다. 색 · 크기 · 아이콘 모양 · 간격은 비교하지 않는다 (이 HTML 은 디자이너용
구조 시안의 입력이다).

읽은 Flutter 파일:

- `lib/screens/a1_home.dart`, `a1_transfer_entry.dart`, `a1_transfer_account.dart`,
  `a1_transfer_amount.dart`, `a1_transfer_confirm.dart`, `a1_transfer_password.dart`,
  `a1_transfer_done.dart`
- `lib/data/sh_dummy.dart`, `lib/data/sh_bank_data.dart`
- `lib/widgets/sh_number_keypad.dart`, `sh_security_keypad.dart`, `sh_bank_sheet.dart`,
  `sh_common.dart` (오류 팝업 · `OutOfScope` · `popToConditionHome`)

표의 "판정" 열: **같음** · **다름** (고친다) · **다름·유지** (고치지 않는다, 이유를
적음).

않는다.

## 5. 고칠 것 (2번 단계)

위 표에서 "다름" 인 것. 화면 이름(`data-screen`)과 흐름 파일이 쓰는 id·`data-action`
은 그대로 둔다.

1. 데이터: 홈 이름 홍길동, 홈·카드 잔액 "금액 숨김", 출금가능금액 1,000,000원, 전액
   1,000,000, 받는 분 김철수 (확인 화면 메모 두 줄).
2. 홈 카드 글자를 Flutter 대로 (IRP 배너, 땡겨요, 7월 소비, 포인트 홍보, 추천서비스,
   자산 연결 배너). 누를 수 있는 것은 [이체] 하나로 둔다.
3. 받는 사람: 받는 사람 7행 삭제, 묶음 수 0개, [검색] 단추(무동작).
4. 계좌: 빈 칸 글자, ⓧ 지우기, 최대 14자리와 경고, ‹ → 받는 사람, ✕ → 받는 사람,
   [다음] 에서 ELB00016.
5. 금액: "아래 계좌로", 받는 계좌의 은행이 입력을 따라감, 잔액에서 멈추는 빠른 금액
   · 숫자 입력, 출금계좌 줄 글자.
6. 확인: "아래 계좌로", 받는 계좌의 은행과 위 그림 글자가 입력을 따라감, 메모 김철수,
   [보내기] 판정 (ETA00325 · ELB00016).
7. 비밀번호: ✕ → 홈.
8. 완료: "아래 계좌로".
9. 오류 팝업 화면 하나 추가 (`data-screen="error"`, 화면 단위 규칙 — 따로 뜨는
   팝업은 화면 하나). [확인] 은 팝업을 연 화면으로 돌아간다.
10. 고르는 버튼 묶음(`num`, `acc-num`, `quick`)을 스크립트 배열로.

## 6. 끝내 다른 것 (맞추지 않음)

| 항목 | 이유 |
|---|---|
| 화면 이름 (`recipient` ↔ `transfer_entry` 등) | 흐름 파일 · 옛 결과 · 검사 A 가 이 이름에 묶여 있다 |
| 홈의 전체메뉴 · 쉬운홈 | 이체 과제 밖. HTML 에서는 무동작 |
| 시각 (로고, 색, 점의 `cur` 상태, 아이콘) | 구조 시안의 입력이라 비교 대상이 아니다 |
| 백도어 계좌 `0` | 실험자 편의 장치. 참가자 화면이 아니다 |
| 과제 금액 판정 | Flutter 도 금액을 판정하지 않는다. 32,000 은 검사기의 흐름 값(truth)으로만 쓴다 |

## 7. 적용 결과 (2026-10-05)

5절의 고칠 것을 모두 적용했다. 검토에서 바뀐 것과 적용하면서 더한 것:

- 오류 팝업은 화면 **둘**이다 — `err-account` (ELB00016), `err-bank` (ETA00325).
  [확인] 과 팝업 바깥(`close-error`)은 팝업을 연 화면으로 돌아간다.
- 계좌 화면의 ‹ 와 ✕ 는 목적지가 같지만(받는 사람) `data-action` 을 나눴다
  (`back-recipient`, `close-account`). 같은 부모 아래 같은 이름 둘은 선택지 묶음으로
  잡혀 보존 장치와 검사 I 에 섞인다.
- 은행 시트의 ✕ 는 `close-bank` 로 나눴다 (예전에는 계좌 화면 ‹ 와 같은
  `back-recipient` 였다).
- Flutter 처럼 다시 들어올 때 비운다 — 계좌 화면(계좌·은행), 금액 화면(금액, 계좌
  [다음] 으로 들어올 때만), 은행 시트(은행 탭).
- 상태 표시줄 글자도 Flutter 의 `4:31` · `67` 로 맞췄다.
- 받는 분 이름 `김철수` 는 Flutter 처럼 고정값이다 (입력이 아니다).

브라우저로 확인한 동작: 14자리에서 멈추고 경고, ⓧ 로 비움, 은행을 고르기 전에는
[다음] 무시, 틀린 계좌 → ELB00016 → [확인]/바깥 → 계좌 화면(입력 그대로), 계좌는
맞고 은행이 틀림 → 금액 → 확인 [보내기] → ETA00325 → 확인 화면, 전액 = 1,000,000
에서 숫자 더 누르면 무시, 정답 경로(신한 · 110234567890 · 32,000) → 완료 "아래 계좌로
32,000원 보냈어요.".

## 8. 계좌번호 키패드 (2026-10-07, 11-11)

더미앱 A1 은 `4cd2179` (병합 `82d44ed`, "A1 계좌번호 화면: 키패드는 입력란을 눌러야
열린다") 에서 계좌번호 화면을 고쳤다. 근거 캡처 두 장(`181550385`, "14자 이상 입력 시")이
모두 입력란을 누른 뒤의 모습이라 키패드가 늘 떠 있는 것으로 재현했었고, 연구자가 실제
앱에서 확인해 보니 들어오면 키패드는 닫혀 있고 계좌번호 입력란을 눌러야 열렸다. 원본
HTML 도 같은 캡처를 같은 방식으로 읽어 처음부터 키패드를 띄우고 있었다 — 입력 중 캡처
한 장이 "늘 떠 있는 상태" 로 읽힌 것이다. 원본을 더미앱에 맞췄다.

| 항목 | 고치기 전 HTML | 지금 HTML = Flutter A1 (`4cd2179`) |
|---|---|---|
| 들어왔을 때 | `#acc-pad` 가 떠 있다 | 보이지 않는다. [다음] 은 맨 아래 그대로 |
| 입력란 | 누를 것이 아니었다 | `#acc-field` 에 `data-action="acc-field"`. 누르면 키패드가 예전과 같은 자리 · 모양으로 열린다 (390×264, [다음] 바로 위) — Flutter 키 `transfer_account_field` |
| 열린 뒤 | — | 이 화면에 있는 동안 열려 있다. 은행 시트를 ✕ 로 닫거나 은행을 골라 닫아도, 오류 팝업(ELB00016)을 [확인] · 바깥으로 닫아도, 금액 화면의 ‹ 로 돌아와도 그대로 (Flutter 는 그 화면을 다시 만들지 않는다). 닫는 동작은 실제 앱에서 확인하지 못해 더미앱도 만들지 않았다 |
| 다시 들어올 때 | — | 받는 사람 → [계좌번호 직접 입력] 으로 들어오면 닫힌 채로 시작한다 (‹ · ✕ 로 나갔다 들어와도) |
| 금액 · 비밀번호 화면 | 늘 떠 있다 | 그대로 (Flutter 도 늘 떠 있다) |

키패드가 숨어 있어도 `acc-num` 버튼 열 개는 DOM 에 있다. 검사 I 의 원본 선택지는
DOM 에서 모으므로 `acc-num` 10 그대로다 (`tests/test_error_paths_browser.py`).

흐름 `flows/original.json` 은 이 전환을 걸음으로 적는다. `account` 도착 바로 뒤에
`{"screen": "account", "click": "[data-action='acc-field']", "state": "키패드 열림 —
계좌번호 입력란을 누른 뒤"}` (방문 이름 `account#2`) 가 있고, 오류 경로 둘도 숫자를 넣기
전에 입력란을 누른다. `required_ids` 에 전환의 두 끝 `acc-field` · `acc-pad` 를 더했다.
모델은 계좌 화면을 두 장 — 들어온 모습과 입력란을 누른 뒤 — 으로 본다
(`docs/input-contract.md` 의 "입력 약속").
