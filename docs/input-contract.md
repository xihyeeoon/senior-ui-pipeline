# 입력 계약 — 앞단이 만들어야 하는 HTML

## 목적

도구의 최종 형태는 "디자이너가 스크린샷을 넣으면 재설계 와이어프레임을 얻는다"
이다. 도구 안에서는 스크린샷을 HTML 로 바꾸는 앞단(읽기)을 먼저 거친다. 그 앞단은
아직 없고, 지금은 사람이 만든 `inputs/original_transfer.html` 이 앞단 결과물의
대역이다.

뒤쪽 — 재구성 루프(`senior_ui/restructure/`), 검사기(`senior_ui/audit/`), 데이터
보존 장치(`preserve.py`) — 는 그 HTML 에서 여러 가지를 읽는다. 이 문서는 그 목록을
적고, 항목마다 스크린샷에서 얻을 수 있는지를 가린다. 앞단을 붙이는 날 연결이 끊기지
않게 하려는 약속이다.

## 요약 — 앞단이 지킬 약속

1. **HTML 과 함께 그 HTML 을 걷는 흐름 파일도 낸다.** 뒤쪽은 원본을 흐름 파일대로
   한 번 걸어 기준값을 만든다. 흐름 파일이 없거나 선택자가 HTML 과 맞지 않으면
   기준값이 비고, 선택지 요약·데이터 보존·검사 I 가 모두 아무것도 보지 못한다.
2. **`data-action` 이 있는 고르는 버튼 묶음은 전부 스크립트 배열로 두고, 화면은 그
   배열로 그린다.** 데이터 보존 장치는 배열로 그려진 선택지만 보호한다.
3. **기술 계약을 지킨다** — `#phone`, `section.screen[data-screen]`, `data-action`
   과 처리기 하나, `__screen()` 등 기록 훅. 전부 (다) 이고 아래 표에 있다.
4. **사람이 보충할 것은 최소로 둔다.** 기본 규칙(다)으로 정하고, 규칙에서 벗어나는
   예외만 사람이 적는다.

분류는 셋이다.

| | 뜻 | 앞단이 할 일 |
|---|---|---|
| **(가)** | 스크린샷으로 알 수 있다 | 이미지에서 읽어 낸다 |
| **(나)** | 스크린샷만으로는 알 수 없다 | 사람이 보충한다 (흐름 파일·입력 양식) |
| **(다)** | 도구가 자동으로 붙이면 된다 | 규칙대로 생성한다. 이미지와 무관 |

## 뒤쪽이 원본을 읽는 경로

원본을 읽는 길은 셋이다. 표의 "어디가 쓰나" 는 이 셋 중 하나를 가리킨다.

1. **프롬프트 본문.** 원본 HTML 전체가 `{{ORIGINAL_HTML}}` 자리에 그대로 들어간다
   (`restructure/prompt.py` 의 `build_prompt`). 모델은 마크업·CSS·스크립트를 전부
   읽는다. 그래서 스크립트에만 있는 동작(자릿수 제한, 키패드 섞기)도 모델에게는
   전달된다 — 검사기가 그것을 보지 않을 뿐이다.
2. **기준값 걷기.** 재구성 루프는 실행마다 한 번 원본을 브라우저로 걷는다
   (`restructure/loop.py` → `audit.drive(원본, flows/original.json)`). 걸음마다
   `audit/probes.py` 의 probe 가 화면을 긁어 스냅샷을 만들고, 검사 A~I 가 그것을
   기준으로 쓴다. 선택지 요약(`choices_block`)과 데이터 보존(`preserved_data`)도 이
   스냅샷에서 나온다.
3. **원문 정규식.** 원본 HTML 글자를 직접 훑는 곳 — 스크립트 배열 선언
   (`preserve.script_arrays`), `alert(`·`confirm(`·`prompt(` 호출(검사 B), 영어
   낱말(검사 F).

`flows/original.json` 은 손으로 쓴 것이고 원본의 선택자를 박아 두었다
(`go-recipient`, `pick-bank`, `#acc-next`, `#pwpad` …). 기준값 걷기는 이 파일 없이
돌지 않는다. 요약 1번 약속이 필요한 이유다.

## 선택지 값 이름 규칙

선택지마다 `data-action` 다음에 값을 담는 `data-*` 를 **하나만** 둔다.
`CHOICE_GROUPS` 는 `data-action` 이 아닌 첫 `data-*` 를 값으로 읽기 때문이다.

| 선택지 종류 | 속성 | 값 | 원본의 예 |
|---|---|---|---|
| 이름 목록 (은행·증권사 …) | `data-<종류>` | 보이는 글자 그대로 | `data-bank="카카오뱅크"` |
| 숫자 키 | `data-v` | 키에 적힌 글자 그대로 | `data-v="0"`, `data-v="00"` |
| 금액 버튼 | `data-v` | 원 단위 정수, 쉼표 없이 | `+1만` → `data-v="10000"` |
| 숫자로 나타낼 수 없는 값 | `data-v` | 영문 소문자 낱말 | `전액` → `data-v="all"` |

배열 원소는 이 값과 같은 글자로 쓴다 (`const QUICK = ['10000', … , 'all']`).
`preserve.backing` 은 배열 원소와 선택지 값이 절반 넘게 겹쳐야 그 배열을 목록의
출처로 본다.

## 선택지 그룹별 보호 여부

데이터 보존 장치(`preserve.py`)는 **스크립트 배열로 그려지는 선택지만** 보호한다.
마크업에 직접 쓴 선택지는 모델이 그대로 옮기든 빼든 도구가 손대지 않는다. 그런데
검사 I 는 둘을 가리지 않고 센다. 그래서 마크업 선택지가 빠지면 보호는 없고 fatal 만
난다. 요약 2번 약속 — `data-action` 이 있는 고르는 버튼 묶음은 길이와 상관없이 전부
배열로 — 이 그 틈을 막는다.

## 앞단의 정확도를 재는 방법 (제안)

사람이 만든 원본 HTML 을 정답으로 둔다. 같은 앱의 스크린샷을 앞단에 넣어 HTML 을
만들고, 둘을 **뒤쪽이 실제로 읽는 것** 으로 비교한다. 픽셀이나 마크업 문자열을
비교하지 않는 이유는, 뒤쪽이 쓰지 않는 차이까지 감점하면 연결이 끊기는 차이와
상관없는 차이를 구분할 수 없어서다.

1. **기준 스냅샷 비교.** 두 HTML 을 각자의 흐름 파일로 걸어 스냅샷을 얻고 다음을
   잰다.
   - 화면: 화면 수, 흐름 단계별 도착 여부 (검사 A 와 같은 판정)
   - 글자: 화면마다 `innerText` 를 낱말로 나눠 재현율·정밀도
   - 선택지: `CHOICE_GROUPS` 의 그룹마다 값 재현율. **검사 I 의 경계 규칙
     (`i_choices.present`)을 그대로 쓴다** — "국민" 과 "국민은행" 을 같은 값으로
     보는 규칙이 비교에서도 같아야 한다.
   - 보호: `split_groups` 결과가 같은가 (어느 그룹이 배열이고 어느 그룹이 마크업인가)
2. **뒤쪽 결과 비교.** 같은 재구성 설정으로 두 입력을 각각 돌려, 원본을 입력으로 한
   검사 결과와 앞단 HTML 을 입력으로 한 결과가 갈리는지 본다. 갈리면 그 차이가
   앞단의 결함이다. 원본 대 원본은 지금 fatal 0 / warning 2 이므로, 앞단 HTML 을
   원본 자리에 넣고 자기 자신과 검사하는 것도 같은 값이 나와야 한다.
3. **(나) 항목은 따로 센다.** 스크린샷에서 원래 얻을 수 없는 것이므로 앞단의
   점수에서 빼고, 사람이 보충한 입력이 HTML 에 반영되었는지만 본다 (예: N1 자릿수가
   스크립트에 들어갔는가).
4. **표본.** 원본 하나로는 부족하다. 사람이 만든 정답 HTML 이 둘 이상 생기면 앱마다
   위 숫자를 내고, 같은 스크린샷을 여러 번 넣어 앞단 자체의 흔들림도 함께 잰다
   (`docs/variance-notes.md` 와 같은 방식).

## 결정 기록 (2026-10-05, Flutter A1 에 맞춤)

원본을 Flutter 더미앱의 A1 이체에 맞췄다 (`docs/original-vs-flutter-a1.md`).

| # | 항목 | 결정 |
|---|---|---|
| 1 | 오류 팝업 | 화면 둘 (`err-account`, `err-bank`). 문구와 뜨는 화면이 다르고, 화면 단위 규칙상 따로 캡처된 팝업은 화면 하나다 |
| 2 | 화면 이름 · 흐름이 쓰는 id · `data-action` | 바꾸지 않는다. 옛 흐름과 옛 결과를 다시 검사할 수 있어야 한다 |
| 3 | 메인의 전체메뉴 · 쉬운홈 | 이체 과제 밖이라 무동작 (Flutter 에서는 다른 화면으로 간다) |
| 4 | 과제 금액 32,000 | 판정하지 않는다 (Flutter 도 하지 않는다). 흐름 파일 `truth` 로만 쓴다 |
| 5 | 정답 값의 자리 | 코드(`audit/flow.py`)가 아니라 흐름 파일의 `truth` 블록. 블록이 없는 흐름(모델이 쓴 흐름 명세 등)은 원본 흐름의 정답을 쓰고, 재구성 루프는 모델이 적은 `truth` 를 무시한다 |

지우기 ⓧ 는 캡처로 보이므로 (가), 팝업 [확인] 의 목적지와 겹치는 배열의 짝짓기
