# 실험 진행 안내

고령 피험자에게 스마트폰으로 이체 과업을 시키고, 원본과 재구성본을 비교하는 실험의
준비·진행·집계 절차. 실험 당일에는 이 문서 하나만 있으면 됩니다.

- 조건 2개: **원본**(신한 SOL 재현) vs **재구성본**(Run 1, 9화면)
- 피험자 내 설계 — 한 사람이 두 조건을 다 합니다. 순서는 번호로 엇갈립니다
- 기록은 자동 — 실험자가 숫자를 받아 적을 일이 없습니다

## 1. 하루 전 준비

**PC와 폰을 같은 Wi-Fi에 둡니다.** 폰이 PC에 접속해야 합니다.

```powershell
cd C:\Users\xihye\senior-ui-pipeline
.\.venv\Scripts\python.exe -m senior_ui.experiment.server
```

주소가 출력됩니다. 폰 브라우저에서 그 주소를 엽니다.

```
http://192.168.0.12:3003/web/session.html
```

**연결이 안 되면** 방화벽입니다. PowerShell을 관리자로 열어 한 번만 실행합니다.

```powershell
New-NetFirewallRule -DisplayName "senior-ui 실험" -Direction Inbound -LocalPort 3003 -Protocol TCP -Action Allow
```

**확인할 것**

- 폰을 **가로로 눕히지 않게** 합니다. 세로 고정을 켜 두세요
- 글자 크기를 기기 기본값으로 둡니다. 폰의 접근성 확대가 켜져 있으면 조건 비교가 깨집니다
- 화면 자동 꺼짐을 5분 이상으로 늘립니다
- 브라우저는 주소창이 보이는 일반 모드로 씁니다. 전체화면 모드는 기기마다 높이가 달라집니다

## 2. 세션 진행

한 사람에 약 15~20분입니다.

1. **피험자 번호**를 넣습니다 (1, 2, 3 …). 화면이 조건 순서를 알려 줍니다
   - 홀수 → 원본 먼저, 짝수 → 재구성본 먼저. 순서 효과를 상쇄합니다
2. **과업**을 고릅니다 (아래 3절)
3. [세션 시작] → 과업 안내 화면이 뜹니다. **피험자에게 소리 내어 읽어 줍니다**
4. [시작]을 누르는 순간부터 시간이 기록됩니다. 폰을 피험자에게 건넵니다
5. 피험자가 송금을 마치면 **자동으로 끝납니다**
6. 결과 요약이 뜨고 자동 저장됩니다. [다음 과업으로]
7. 두 번째 조건을 같은 방식으로. 끝나면 세션 종료 화면

**중간에 그만두어야 할 때** — 피험자가 포기했거나, 도저히 못 하거나, 중단을 요청할 때:

> 화면 **오른쪽 위 구석을 3초간 길게** 누릅니다 → [중단하고 기록]

거기까지의 기록이 "중단"으로 남습니다. 피험자가 실수로 누를 수 없도록 3초로 잡았습니다.

**진행 중 하지 말 것**

- 조작 방법을 알려 주지 마세요. 어디서 막히는지가 이 실험의 자료입니다
- "그거 아니에요", "위에 있어요" 같은 힌트도 개입입니다
- 피험자가 물으면 "편하신 대로 해 보세요"라고만 합니다
- 정말 막혀서 괴로워하면 중단하세요. 완료하지 못한 것도 결과입니다

## 3. 과업 두 가지

| | 지시문 | 무엇을 보는가 |
|---|---|---|
| **긴 과업** | 김시현 씨에게 1만 원을 보내 주세요. 계좌번호는 3333-0000-0000-0 이고, 카카오뱅크입니다. 저장된 목록에 있더라도 계좌번호를 직접 넣어서 보내 주세요. | 13자리 입력과 은행 찾기. 재구성본이 겨냥한 구간입니다 (원본은 은행 타일 66개, 재구성본은 앞자리로 추정해 예/아니오) |
| **짧은 과업** | 김시현 씨에게 1만 원을 보내 주세요. | 저장된 사람을 고르는 경로. 양쪽 다 목록이 있어 차이가 작습니다 |

**긴 과업을 주력으로 쓰시길 권합니다.** 짧은 과업은 두 설계가 거의 같은 길을 지나가서
차이가 잘 안 납니다. 시간이 허락하면 긴 과업만 두 조건으로 하고, 남으면 짧은 과업을
추가하는 편이 낫습니다.

지시문을 바꾸려면 `senior_ui/experiment/server.py` 위쪽의 `TASKS` 를 고칩니다.
페이지를 열 때 폰이 읽어 가므로 서버만 다시 띄우면 됩니다.

## 4. 수집되는 자료

세션마다 `sessions/P01_1_original.json` 같은 파일이 생깁니다.

| 지표 | 뜻 |
|---|---|
| 완료 여부 | 송금까지 갔는가. **가장 중요한 결과입니다** |
| 걸린 시간 | [시작]부터 송금 완료까지 |
| 누른 횟수 | 전체 탭 수 |
| **빗나간 탭** | 누를 수 없는 곳을 누른 횟수 = "어디를 눌러야 할지 몰랐다" |
| 되돌아가기 | 뒤로 간 횟수 = "잘못 왔다" |
| 지우기 | 입력을 지운 횟수 = 손떨림·자릿수 착오 |
| 화면별 체류 | 어느 화면에서 시간을 썼는가 |

원본 기록(모든 탭의 좌표·대상·타깃 크기)도 함께 저장되므로, 나중에 다른 지표가
필요해져도 다시 계산할 수 있습니다.

**개인정보는 기록하지 않습니다.** 이름·나이·성별은 파일에 들어가지 않습니다. 피험자
번호와 실험 기록뿐입니다. 인적 사항은 별도 동의서로 관리하세요.

## 5. 집계

언제든 중간 집계를 볼 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m senior_ui.experiment.report
```

논문·발표용으로 파일까지 만들려면:

```powershell
.\.venv\Scripts\python.exe -m senior_ui.experiment.report `
   --out results\session-report.md --csv results\sessions.csv
```

- `session-report.md` — 진행 현황, 피험자별, 조건 비교, 화면별 체류, 막힌 지점
- `sessions.csv` — 세션당 한 줄. SPSS·R·엑셀에서 통계 검정을 돌릴 때 씁니다

**통계 검정은 이 도구가 하지 않습니다.** 표본이 작고 피험자 내 설계라 어떤 검정을 쓸지는
연구자가 정할 문제입니다. 중앙값·평균·범위와 원자료를 주는 데까지가 이 도구의 몫입니다.

## 6. 예비조사에서 확인할 것

본실험 전에 **고령자 1~2명**으로 먼저 해 보세요. 여기서만 드러나는 것들입니다.

- 지시문을 알아들으시는가. "계좌번호를 직접 넣어서"가 통하는가
- 폰을 쥐는 자세에서 화면 아래쪽 버튼에 손이 닿는가
- 15~20분이 부담스럽지 않은가
- 과업을 시작하기 전에 폰 자체를 어려워하시는가 (그렇다면 연습 시행이 필요합니다)

예비조사 데이터는 본실험에 섞지 마세요. 피험자 번호를 90번대로 주고 나중에 빼면 됩니다.

## 7. 문제가 생기면

| 증상 | 해결 |
|---|---|
| 폰에서 주소가 안 열림 | 같은 Wi-Fi인지 확인 → 방화벽 규칙(1절) → PC IP가 바뀌었는지 서버 출력 확인 |
| "저장 실패"가 뜸 | **화면을 닫지 마세요.** Wi-Fi를 확인하고 서버가 살아 있으면 자동으로 재시도되지 않으므로, 기록을 손으로 적어 두고 세션을 다시 진행합니다 |
| 화면 아래가 잘림 | 브라우저를 전체화면이 아닌 일반 모드로. 그래도 잘리면 기기 크기를 알려 주세요 |
| 과업이 저절로 안 끝남 | 송금 완료 화면까지 갔는지 확인. 비밀번호 4자리를 다 누르면 완료됩니다 |
| 잘못된 번호로 시작함 | 그대로 진행하고 나중에 파일 이름을 고치거나, 중단 후 올바른 번호로 다시 시작 |

## 8. 이 실험이 답하는 것과 답하지 않는 것

**답하는 것** — 규칙 기반 수리로는 바꾸지 못한 구조를 LLM이 다시 짰을 때, 고령 사용자가
실제로 과업을 더 잘 끝내는가.

**답하지 않는 것**

- 재구성본이 실무에 낼 수 있는 물건인가 — 비밀번호 셔플 제거 등 보안 판단이 남아 있습니다
- 어느 변경이 효과를 냈는가 — 28건을 한꺼번에 바꿨으므로 개별 기여는 분리되지 않습니다
- 규칙 기반 수리가 사람에게 어떤가 — 이번 실험에 넣지 않았습니다 (audit fatal 7건이라
  과업이 중간에 막힐 수 있습니다)
